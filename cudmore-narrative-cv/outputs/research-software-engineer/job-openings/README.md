# RSE Job-Opening Briefs

This directory contains job-specific editorial briefs for advertised positions pursued with the Research Software Engineer application packet.

Each brief interprets one employer's requirements and records how the existing RSE materials should be tailored for that position. These files are planning and application-support documents. They are not independent sources of facts about Robert Cudmore's experience.

## Relationship to Other Files

- [`../jobs.md`](../jobs.md) is the application index and status tracker.
- [`../job-descriptions/`](../job-descriptions/) contains saved employer job descriptions when available.
- Files in this directory summarize role priorities, relevant evidence, factual boundaries, and application strategy.
- Job-specific cover letters remain in the parent `research-software-engineer` directory.
- The shared RSE CV, platform descriptions, technical skills, and project resources remain the baseline application materials unless a brief records an approved job-specific exception.

## Source Hierarchy

Use the following source order when creating or updating a job-opening brief:

1. Robert's direct factual statements and corrections.
2. The canonical root Markdown sources, especially `outline.md`, `narrative.md`, `technical-skills.md`, `section-guide.md`, and `project-links.md`.
3. The current files in `outputs/research-software-engineer/`.
4. The employer's job description for its requirements.
5. External reviews and generated drafts as advisory material only.

Job descriptions establish employer requirements. They do not establish facts about Robert's experience. Never infer an undocumented qualification from wording in a posting.

## Expected Contents

A job-opening brief should normally include:

- **Posting Information:** employer, title, posting link, requisition number, location, work arrangement, review date, and application status.
- **Role Priorities:** a concise interpretation of the position and its principal requirements.
- **Evidence to Emphasize:** supported experience and projects most relevant to the position.
- **Factual Boundaries:** missing qualifications, adjacent experience, and claims that must not be made.
- **Application Direction:** guidance for the cover letter and any necessary job-specific adaptations.
- **Requisition-Specific Questions and Answers:** optional; include when an application form requires written responses.

## Working Rules

Use the current brief as the editing baseline and preserve manually revised language unless a change is explicitly approved. Keep each brief specific to one advertised position. Do not change the shared RSE materials merely to satisfy an individual posting.

Distinguish direct experience from adjacent or transferable experience. Describe future architectural capabilities as future capabilities, not implemented features. Keep detailed application status in `jobs.md`, and update both files when a material status change affects the brief.
